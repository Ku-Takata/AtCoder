# C_02

`C_02_IMPROVEMENT_SPEC.md`を基に、C_01の通常探索で選んだ最良解をcheckpointとして保存し、余った時間でだけ追加短縮する単独Rustコードです。外部クレートは不要です。

## 要件との対応

| 要件 | 実装 |
|---|---|
| T: checkpointとtail | 実装済み。SA・通常候補評価・候補プールの扱いはC_01と同じ。tailはA44の最良解決定後だけ実行 |
| T: 締切 | main開始から1,745msと、従来a44開始から1,745msの小さい方。残り5ms未満ならスキップ |
| T: 再短縮 | 最初は最大15ms、残り時間の1/5を上限としてgeometry/bridge/prune/cycleを再適用。その後は逆順からcompactを探索し、改善後に最大2msのbridge/prune/cycleを挟む |
| T: 走査状態 | 操作列・trace・方向・カーソル・列のversionをセッションで保持。編集後は近傍を再訪し、古い窓キューを破棄。方向は交互に変更 |
| K: 1手判定 | 実装済み。不一致1～2マスから出発・着地点を絞り、全合法kを列挙。出発点・着地点の両方の帰巣を正確に処理 |
| K: 早期枝刈り | 候補をバッファへ入れる前に不一致マス数の下界と、帰巣で減った色個数を確認 |
| K: 候補バッファ | 深さ別のVecを再利用。候補は操作と両端の変更・帰巣した色列を持ち、96バイト状態は再帰時だけコピー。undoは使用しない |
| K: 探索開始深さ | 不一致数/2の切上げから反復深化。最大4手・2,000 DFS呼出し・1ms/窓を維持 |
| M: 窓キャッシュ | 昇順のR座標・開始状態・終了状態・遷移ルールの完全なキーで判定。成功経路と完全に探索した深さを記録。最大4,096窓 |
| M: 予算打切り | NodeLimit/TimeLimitとExhaustedを区別。中断した深さは解なしと扱わない。同じversion・深さ・予算での重複試行は一時的な印で抑制 |
| R: 帰巣なし前後方向探索 | 未実装。今回は仕様が主案としているT+K+Mまでを実装 |

採用する区間置換は元より短く、保持する独立操作も含めて区間を実再生し、元の終了全盤面と一致する場合に限ります。変更後にtraceを更新し、時間切れならそこで探索を終了します。tail最後に全操作列の合法性・全帰巣を確認し、もし不整合があれば保存したcheckpointへ戻します。

このため同じ実行内では `final_ops <= checkpoint_ops` を守ります。別実行のC_01との手数一致は保証しません。時間制限型SAの反復数は実行時間の揺れやコード配置の違いに影響されます。

## 切替

| 引数 | 内容 |
|---|---|
| `--tail=off` | 追加探索なし。C_01と同じ通常探索経路 |
| `--tail=legacy` | 既存の幾何学的短縮とC_01のLocalSearchをtailへ再適用。逆順走査と同一窓の再試行抑制を含む |
| `--tail=compact-fast` | T+K+M。標準設定 |

通常候補評価の `--post=local` も従来どおり標準です。B01の6件ではtailを呼ばず、B01固有の探索や時間配分は変更していません。任意拡張Rの `--tail=mitm` は未実装なので指定できません。

`legacy`は元のDFSの訪問数をcallsとして記録します。詳細なgenerated/expanded/terminal_checksは高速版用で、legacyでは0です。高速版のexpandedとC_01のcompact_nodesは同じ定義ではありません。

## コンパイルと正しさの確認

作業フォルダで実行します。

```powershell
rustc --edition=2021 -O C_02.rs -o C_02.exe
rustc --edition=2021 -O --test C_02.rs -o scratch\C_02_tests.exe
.\scratch\C_02_tests.exe
```

C_01の6テストを維持し、7テストを追加しました。計13件が成功しています。

- 1マスだけ異なる帰巣、出発点の帰巣で最終高さがkより低くなる例。
- 残り1手判定とR内全合法1手列挙の比較。
- 高速遷移・差分不一致数・差分色個数と基準物理の比較。
- 高速探索の経路と元の局所探索、深さ別バッファの使用。
- R・探索深さ・予算打切りを混同しないキャッシュ。
- off・即時時間切れ・探索完了時のcheckpoint保持と全帰巣。
- 編集後のversion変更、trace再構築、窓添字の整合性。

## 今回の測定結果

標準の`compact-fast`を100ケース各1回、C_01と交互に実行した結果です。

| 指標 | C_01再測定 | C_02 |
|---|---:|---:|
| 合計手数 | 31,549 | 31,374 |
| 不正・未帰巣 | 0件 | 0件 |
| 2秒以上 | 0件 | 0件 |
| 1,800ms超 | 0件 | 1件 |
| 最大外部時間 | 1,792.911ms | 1,808.425ms |

今回の同条件測定では175手（0.555%）改善し、51勝30分19敗でした。同一実行内のcheckpoint合計は31,532手、tail後は31,374手で、tail自体が158手を51ケースで削減しています。全100件でfinal <= checkpointを確認しました。

tailの削減内訳は最初のgeometry等が31手、局所探索が121手、改善後の整理が6手です。局所探索の逆順窓は114,026回、順方向窓は64,071回。完全探索済みキャッシュのヒットは90,308回、一時的な重複試行抑制は53回でした。成功経路キャッシュのヒットは0回でした。

過去のC_01記録31,312手に対しては62手多く、歴史的最良記録の更新はできていません。今回は同条件の基準に勝ち、同一実行内のtail効果も確認できましたが、別実行のSA・時間の揺れを含むため、どの実行でも必ずC_01より良くなるとは扱いません。

測定後にC_02のコードやパラメータは変更していません。結果の詳細は新しい評価フォルダのREPORT.mdに保存しています。
